# Learnings: 0032, a Principal's roles come from `access`' assignments

- **Roles live in the snapshot, not the token.** `app_authz::RuleSet` carries each subject's assigned roles (`RuleSet::assigning`), and `access::Rules::refresh` builds them with the grants. `Authorizer::principal(sub)` = `user` + assigned + `admin` for bootstrap admins. The default `PrincipalResolver` is the `Authorizer` itself (`impl PrincipalResolver for Authorizer` in `app_web::auth`); `jwt_checker` uses the `Arc<Authorizer>` already in request data, so the server needs no resolver line. `Claims` has no `roles`; `JwtVerifier::issue(subject, ttl)`.
- **Bootstrap admins are on the `Authorizer`** (`with_bootstrap_admins`), not stored: they survive every `replace`, and the service reads them for its lockout checks. `server::main` passes `AppConfig::bootstrap_admins()` (`APP_BOOTSTRAP_ADMINS`, a comma-separated string, since figment won't split a list from env). **figment's `Env` parses every value**: `12345` becomes a number and `true` a bool, so a `String` field fails to load. `AppConfig::figment` ignores the key in `Env::prefixed` and merges `Env::var(..)` raw instead; do the same for any other free-text env value.
- **Every signed-in caller now holds `user`**, so "a token without the user role is kept out" tests are gone from every module and the journeys: the scenario can't happen. A refusal journey needs an operation `user` isn't granted: `access`' own (`list_roles`) is the handy one; a non-author reading a note is `404`, not `403`.
- **Module tests (no `access`) give roles with `Authorizer::assign_in_memory(subject, roles)`** (behind app-authz's `testing` feature, which those modules' dev-dependencies enable), which replaces that subject's assigned roles in the rule set in force. Drivers that sign in per request (`crates/reference/notes`' `by(..)`) reset the author to plain `user` first, since roles are per subject now, not per token.
- **Seeds get the `Context`** (`Module::with_seed(|ctx| ..)`, `module.seed(&ctx)`), so a seed can build another module's API: `crates/reference/users`' `module(access::assignments)` assigns Alice `admin` through `access_api::RoleAssignments::ensure_assigned` as `System` (idempotent: a conflict is `false`). `seed::standard(&pool)` stays role-free so that module's own tests need no `access`.
- **`access::assignments(ctx)` builds an `AccessService` with empty `Modules`**: assigning reads nothing of what can be granted. Don't call grant or catalog use cases through it.
- **Assignment events are keyed `"{role.len()}:{role}:{subject}"`** (`access_api::events::v1::assignment_key`), unambiguous whatever the strings hold; `access.unassigned` keeps each removed pair's version so a re-assignment continues it (as `access.deleted_role` does for roles).
- **`unassign_role` takes `subject` and `role` as query parameters**, not path segments: OIDC subjects can hold `|` or `/`.
- **Proving "no DB read"**: close the pool (`ctx.pool().close()`) and call `get_access_catalog`, which reads only memory; only resolving the Principal could touch the DB.
- **Refreshing `.sqlx` without touching the shared dev DB**: `pg_dump --schema-only app | psql scratch_db`, apply the new migration with `SET search_path TO access;`, then `SQLX_OFFLINE=false DATABASE_URL=<scratch> cargo bin sqlx prepare --workspace -- --all-targets`. Verify seeds the same way (`cargo run --bin migrate`, then `--bin seed --features seed` with `DATABASE_URL` on a scratch DB).
- **After `make init`, no seed makes the dev sign-in an admin**: `scripts/init.sh` adds `dev: export APP_BOOTSTRAP_ADMINS ?= <dev subject>` to the Makefile (`.env`, which the Makefile includes, still wins, and nothing copies `.env.example`) and sets the same value in `.env.example`. New access operations still touch `OPERATIONS`, `TOOLS` in `composed_app.rs`, `TOOLS` in `scripts/init.sh`, and `access_ops` (sorted) in `scripts/check-init.sh`.
- **`make check-init` fails on the whole word `users` (or `notes`, …) anywhere outside `crates/reference/`**, comments, `crates/AGENTS.md` and `.factory/learnings/` included, unless the line also names `crates/reference/`. Say "the accounts it seeds", or name the path. `make check-changed` doesn't run it; `COMPOSE_PROJECT_NAME=rust-react-template` lets both reuse a Postgres another checkout already runs on :5432.
- **Seeded Alice is an `admin`** (the dev sign-in), so in journeys `as_user(USER_ID_ALICE)` acts as an admin: use Bob for plain-user behaviour.
