# Learnings: 0054 Schedules

- **A Schedule's run is a deferred job** in `messaging.job` (`deferred = true`; queue, event type and key all the schedule's name; payload `{"slot": ..}`). The partial unique index `job_deferred_key_idx` is the whole "no overlap" mechanism: `Worker::schedule` inserts `ON CONFLICT (queue, key) WHERE deferred AND dead_at IS NULL DO NOTHING`, and a conflict means a run is pending or running, so the slot is skipped and logged. A dead letter steps aside, so the next slot runs afresh.
- `Worker::schedule` locks due rows of `messaging.schedule` `FOR UPDATE SKIP LOCKED` and moves `next_at` past now in the same transaction as the insert: that, not the index, is what stops two workers creating one slot twice.
- The tick uses the cron text stored in `messaging.schedule` (what `migrate` registered), not the build's own `CRON`, the same way the relay follows `messaging.subscription`.
- The cron parser is hand-rolled in `crates/common/db/src/cron.rs` (`app_db::Cron`), the only file that knows how slots are found; the ADR 0043 text records why no crate was taken.
- `Handlers::every::<S>` stores the handler in the same `jobs` map as deferred jobs, so `claims()` covers schedules with no extra code; `Handlers::schedules()` is what `migrate` registers.
- `migrate` and `worker` check expressions with `server::check_schedules::<C>(&ctx)` right after connecting (handlers need a `Context`, so a pool), before migrating anything. `Worker::run`/`drain` also call `check_schedules`, which refuses a schedule `migrate` hasn't registered.
- **Tracing log assertions across parallel tests are racy**: a thread with no subscriber that reaches a `warn!` callsite first can cache it as never enabled while another test is installing its capture. The delivery tests' `LoggedErrors::capture_at(level)` now calls `tracing::callsite::rebuild_interest_cache()`, and every test that reaches the "slot skipped" warning captures from its start. Without both, the log assertion failed about 1 run in 15.
- Running DB tests against a private Postgres: `query!` needs the migrated `app` database at compile time but tests need `DATABASE_URL=.../postgres` at run time, so refresh `.sqlx` first (`SQLX_OFFLINE=false DATABASE_URL=<url>/app cargo bin sqlx prepare --workspace -- --all-targets`), then run tests with `SQLX_OFFLINE=true DATABASE_URL=<url>/postgres`.
- In zsh, `set -- $pair` doesn't word-split; wrap such loops in `bash -c`.
- A driver whose clock starts at midnight and moves past 03:00 now runs the reference module's nightly purge in `run_pending_events()`. It is harmless today, but a test that counts jobs or announced deletions after crossing 03:00 will see it.
