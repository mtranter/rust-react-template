# Learnings: 0078, Areas declare `needs`; `get_my_permissions`

- **Three kinds of operation** now live in `crates/server/src/exempt.rs` (was `public.rs`): `PUBLIC`, `SIGNED_IN`, and everything else in some `OPERATIONS`. `scripts/init.sh` edits `exempt.rs` (empties `PUBLIC`); keep its path in step if you move it again.
- **Planning an arbitrary resource/action** for a principal: `RuleSet::plan_named(principal, kind, action)` on `authorizer.current()`. Every declared resource/action pair comes from `Policies::catalog(&rule_set).resources[*].actions[*].name` — there is no other public enumerator.
- **`dump-spec --actions`** prints every declared `<resource> <action>`; `check-modules.sh` uses it to check the SPA's Areas' `needs`. The generated TS client can't be used for that: the catalog's resource names are runtime data, not types.
- **`needs: { resource: "..", action: ".." }` must stay on one line** in `capabilities.ts`: `check-modules.sh` greps it, and counts `to: "` lines to make sure every Area has one.
- **Vitest's default `get_my_permissions` answer** is in `src/test/may-use-everything.ts`, a second `setupFiles` entry, because `vitest.setup.ts` is type-checked by `tsconfig.node.json` (no `@/` alias, no DOM) and can't import the shell's registry. It re-adds its handler in a `beforeEach`; a test's own `server.use(holding(..))` wins. MSW matches the first handler of a `server.use(a, b)` call, so put a `holding(..)` before `...accessApi(..).handlers` (which holds `adminPermissions`).
- **Access pages no longer gate on anything client-side**: they render their lists, and a `403` shows as `LoadFailed`'s refusal. That makes more requests in tests that visit `/access/*` as a non-admin; use `notAnAdmin` (which also answers permissions without access' actions).
- **Sign-in tests**: any accepted request (`200`) clears `Session`'s "just came back from signing in" mark, and sequential `401`s each renew once. A test that wants the 401 to reach the screen must refuse every request the page makes, and can't expect exactly one `signinSilent`.
- `new-module.sh` anchors its registry insertion on the `/** Every app, and the platform` doc comment of `registry` in `capabilities.ts`; change that comment and you break `make check-init`.
