# Learnings: 0027, every operation has a Principal past its Module's gate and its action's policy

- **The Authorizer lives on `app_module::Context`** (`with_authorizer`, `authorizer()`). `Context::new` starts with an empty rule set, which denies every user: a test driver or binary that forgets `with_authorizer(..)` gets `403` everywhere, not a silent allow. The server puts `ctx.authorizer()` in request data in `server::app::api`, beside the `JwtVerifier` and an `Arc<dyn PrincipalResolver>`; a module's `TestApi` wire must add both the verifier and `ctx.authorizer()` (needs `poem::EndpointExt` in scope for `.data`).
- **`Caller<G>` is a hand-written `ApiExtractor`** (`crates/common/web/src/caller.rs`) delegating `register`/`security_schemes` to `JwtAuth`, so the spec shows the same `JwtAuth` requirement. Refusals are returned as `poem::Error::from_response(ApiError::from(err).into_response())`, which `render_error` passes through unchanged.
- **`Module::with_policies` takes a closure returning a `PoliciesBuilder`, not built `Policies`**, so `Module::policies()` can name the module (`PoliciesError { module, source }`) when the build fails: a `PolicyError` alone names only the file and line.
- **Idempotency keys are scoped per token subject**, so once requests carry real tokens, a test that reused a key across two different callers stopped seeing `idempotency_key_reused`. Vary the request, not the caller.
- **`make init` unregisters the reference modules**: anything in `crates/server/tests/` that names `notes`/`users` stops compiling after it (`make check-init` catches it). Tests that need a real module's policies belong in `crates/reference/journeys/`; `composed_app.rs` uses a module of its own (`Gadget`). `scripts/init.sh` also empties `PUBLIC`, since `register_user` goes with `users`.
- **`new-module.sh` renames only the paths it is told to**: a new template file whose name contains `widget` needs its own `path=${path/...}` line (done here for `core/policies/widget.yaml`).
- **There was no dev sign-in.** The Vite dev proxy now mints an HS256 token (seeded Alice, role `user`) with the dev secret for every `/api` request (`frontend/vite.config.ts`). Production SPA sign-in is still not built.
- zsh: `grep --include=*.rs` fails with "no matches found" unless quoted (`--include='*.rs'`).
