# Learnings: 0028, row-level authorization (one row checked, lists filtered in SQL)

- **The list's type is `app_authz::Rows` (`All` | `Where(filter)`), not `Scope`** as the ticket sketched: `app_authz::Scope` already exists (a grant's `Any`/`Named` scope), and the glossary's **Scope** is a named condition. `Plan::rows()` is `None` for `Denied`; `Authorizer::rows::<R>(..)` turns that into `Forbidden`.
- **404 vs 403 needs a resource's view action**: `Resource::VIEW: Option<Self::Action>` (defaults to `None`, so every refused row is `404`). `Authorizer::check(principal, &plan, &row)` plans `VIEW` itself to choose.
- **The archived DENY now answers before the domain does**: editing, deleting or changing the items of an author's own archived note is `403` (`forbidden`), no longer the domain's `409` `conflict`. The domain rule stays, for `System`.
- **The note's `list` grant moved into the `author` scope** (`crates/reference/notes/core/policies/default_grants.yaml`): a list applies its own action's plan (ADR 0040), so with `list` unscoped a user would still list everyone's notes.
- **SQL semantics of `push_scope`** (`crates/common/db/src/scope.rs`): it pushes negation down rather than writing `NOT (..)`, because in memory a comparison with a row's `null` is plainly false while SQL's `NOT (NULL)` is `NULL`. `!=` is `IS DISTINCT FROM`. A value the column's kind can't hold (a non-uuid `P.id` against a uuid column, an uppercase uuid) becomes a constant `FALSE`/`TRUE` instead of a cast that would fail with a 500. A uuid matches only in the lowercase hyphenated form, because that is the only form `Resource::attr` gives it. An expression column (`archived_at IS NOT NULL`) is parenthesised. `crates/common/db/tests/push_scope.rs` checks all of this against `Filter::matches` on real Postgres.
- **The agreement test can't live behind the API alone**: the list endpoint only plans `List`. Each module's driver has `ids_where::<C: Columns>(rows)`, which runs the same `push_scope` over the table, and `assert_lists_agree` loops over every action. The module exports its `XColumns` from `lib.rs` so the test can name it and can also define a deliberately wrong mapping (`MisreadAuthor` in `crates/reference/notes/core/tests/notes/behaviours/scoping.rs`).
- **Projections' searches (`crates/reference/note-search`, the template's `search`) refuse any plan but `Allowed`**. They have no `Columns`, so they can't apply a scope yet (the ticket's open question).
- **Journeys read as an `admin`** (`App::note` in `crates/reference/journeys/`) now that a plain `user` only sees their own notes.
- **`make prepare`/`db-up` fail when another checkout's Postgres holds port 5432.** Run `make` with `COMPOSE_PROJECT_NAME=<that project>` (here `rust-react-template`) to reuse it. `.sqlx` entries for removed `query!`s were deleted by hand: they are the `SELECT COUNT(*)` totals, now built by `QueryBuilder`.
- **`make check-init` greps the whole tree, uncommitted `.factory/learnings/` and `crates/AGENTS.md` included, for the whole words `notes`/`users`/`note-search`.** A line passes only if it also contains `crates/reference/`, so name reference code by its path. It takes over 10 minutes from cold, which is longer than one foreground command may run: run it in the background.
- **An operation's summary is its MCP tool's description and is published in `frontend/openapi.json`**: when a policy changes what an operation answers (the archived `409` became `403`, another user's note `404`), update the handler's doc comment in `crates/reference/notes/core/src/web/handlers.rs` and `make spec`, or review fails it. Grep the handlers for the old status code.
- **A repository's `list` takes its rows as `rows: &Rows`** and names the fetched records `found`, so the parameter isn't shadowed before the total's `push_scope` uses it.
- **`push_scope` parenthesises every column that isn't a plain (dotted) identifier**, not only those with whitespace: `a||b` would otherwise bind wrongly.
