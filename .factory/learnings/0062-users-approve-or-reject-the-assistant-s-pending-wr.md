# Learnings: 0062 deciding the assistant's pending writes

- **The outbox holds one event per (topic, key, version)** (`messaging.outbox_event_idx`). A use case that has several things to announce on one root (rejecting each pending call, then posting the message) saves once per event, each bumping the version, rather than publishing several events at one version.
- **The `idempotency_key` reaches a tool only if its operation is served through `app_web::Idempotent`.** `Toolbox` refuses an argument the tool doesn't declare, so `CallerTools::call` adds the key only when the tool's input schema has `idempotency_key`. The assistant driver's stand-in API is now `Idempotent<AppOperations>` behind `ctx.idempotency()`, as the server's is. Declaring `Idempotency-Key` yourself on an operation that `Idempotent` also wraps makes "two arguments named `idempotency_key`", and `Toolbox` drops that tool without a word (the tests saw "no tool is named `create_list`"). Read the header from `&poem::Request` instead.
- **Deciding retries its own lost race.** Two decisions on calls of the same step load the same version. The loser's save is `412`, so `decide` reloads and runs again (up to 3 times), and the write is replayed under its key rather than run twice. This is the one place where "a lost race is stale, never retried" doesn't hold, and the reason is that the key makes the retry safe.
- `decide_tool_call` takes no `If-Match`: the call's status is its guard (`409` once decided). The turn goes back to the model only once no call of its step is still pending. Until then, the stream is just `decided`, plus `toolResult` for an approval, then `finished`.
- The approval card needs the operation's summary, which the SPA can't know. The server fills `summary` on `approvalRequired` (from the turn's surface) and on each stored tool call in `get_conversation` (from the `Toolbox` in request data, `ConversationResponse::summarised`). The summary is the description's first paragraph, since `Toolbox` joins summary and description with a blank line.
- Biome's `useSemanticElements` refuses `role="group"` on a div: wrap the card in a `<section aria-label>`, whose role is `region`.
- A new assistant operation goes in `REST_ONLY` and in `platform_ops` in `scripts/check-init.sh`.
