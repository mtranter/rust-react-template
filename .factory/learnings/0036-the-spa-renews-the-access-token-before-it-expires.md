# Learnings: 0036 token renewal and 401 retry

- `oidc-client-ts`' `signinSilent()` picks the path itself: the refresh-token grant when the stored user has a `refresh_token`, otherwise a hidden iframe with `prompt=none` sent to `silent_redirect_uri`, which defaults to `redirect_uri` (`/auth/callback`). The iframe loads the whole SPA, so `src/main.tsx` checks `isSilentRenewal()` (framed and on `/auth/callback`) and only calls `signinSilentCallback()`, which posts the URL to the parent. The parent does the code exchange.
- You can test both renewal paths with a **real** `UserManager` (`metadata` given inline, the token endpoint answered by MSW), with no module mocks: see `src/lib/sign-in/session.test.ts`. For the iframe path, read the `si:s` state from `sessionStorage` and dispatch a `MessageEvent` with `{ source: "oidc-client", url }` and `origin: window.location.origin`. jsdom logs "Not implemented: navigation" when the iframe navigates, on its own virtual console (`window.jsdom.virtualConsole`, its `jsdomError` event), which a spy on the test's `console.error` doesn't reach: `quietNavigation()` in that test swaps its listeners.
- An `ID token` in tests can be unsigned (`alg: none`): oidc-client-ts reads claims and doesn't verify signatures.
- In `server.use(a, b)` within one call, `a` wins over `b`. Put the overriding handler first when spreading a fixture's handlers after it.
- Renewal scheduling: a renewal that returns a token already inside the 60s margin must not reschedule at once, or it loops (the fake-timer test caught this).
- `.env.example` said the sign-out redirect was `<origin>/`. The code uses `<origin>/auth/signed-out`; that's fixed now.
- `make check-changed` runs `docker compose up -d postgres`, which publishes 5432 under this worktree's project name, so it fails when another checkout's Postgres already holds the port. `COMPOSE_PROJECT_NAME=rust-react-template make check-changed` reuses the running one instead. The tests create their own databases, so sharing it is safe.
- "Never loops" has to hold across page loads, not just within one: a 401-triggered sign-in at a provider with a live session comes straight back, so a token the API always refuses (wrong audience) bounced the tab for ever. `Session.signInAgain` keeps a `sessionStorage` flag until a request is accepted.
- `vitest.setup.ts` clears `sessionStorage` after each test, so sign-in state never leaks between tests; within one test it persists, which is how a screen test simulates coming back from the provider (`cleanup()`, then render again).
- `make check-init` (CI's `init` job, not part of `make check-changed`) fails if any line outside the reference code uses the whole words `notes`, `users`, and so on (`scripts/check-init.sh`), including in prose: "`signInAgain` notes that sign-in" failed CI. Before committing docs, grep the added lines for those words.
