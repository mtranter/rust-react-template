# Learnings: 0026, the `app-authz` engine

- **YAML with line numbers: `saphyr` 0.3.** `serde_yaml` is archived (poem still pulls it in, under an ignored advisory). `saphyr::MarkedYaml::load_from_str` gives a tree whose every node, map keys included, has a `span.start.line()` (1-indexed). `crates/common/authz/src/yaml.rs` converts it to an owned `Node` and reads mappings with `Fields`, whose `finish` refuses any key nobody read, which is how "every other field is refused, naming the line" stays one line of code per mapping. Duplicate keys are a scan error by default.
- **`include_str!` loses the file name**, and every refusal must name it, so policy files go in as `app_authz::policy_file!("policies/note.yaml")` (a `PolicyFile { name, source }`, the path relative to the calling crate's root) rather than the bare `include_str!` the ticket sketched.
- **Action enums use strum.** `app_authz::Action` is blanket-implemented for any `Copy + Eq + Debug` enum deriving `strum::VariantArray` and `strum::IntoStaticStr`; use `#[strum(serialize_all = "camelCase")]`, and `#[strum(serialize = "items:add")]` for a `:`-segment name. A consumer crate needs `strum.workspace = true`.
- **Wildcards are per `:` segment**: `items:*` matches `items:add`, not `items` or `items:add:all`; a lone `*` matches everything. Rule patterns are expanded against the resource's actions when loading, so the rule set is a lookup by (resource, action).
- **Derived roles are expanded when loading** into plain rules over their `parentRoles`, with the derived role's condition ANDed to the rule's. A derived role's attributes are checked against every resource whose policy imports its set, so a set shared by two resources may only use attributes both have.
- **`Filter` is simplified as it is built** (`Filter::all/any/none`: constant folding, flattening, dedup, absorption), so a plan is `Allowed`/`Denied` exactly when nothing is left to check against a row. Absorption matters: `user` + `admin` editing otherwise leaves `any(all(author, not archived), not archived)`.
- **Semantics left for 0027's SQL**: `Filter::Eq(a, Value::Null)` means "is null" (in memory `Null == Null`), and a comparison with an attribute `attr()` doesn't answer is false (`None(..)` of it is then true). A `P.attr` the principal lacks makes its comparison `False` before anything is pushed down.
- `scripts/check-module-deps.sh` now also fails a pure `common` crate (its `pure_common` list) depending on any non-pure workspace crate: `deny.toml`'s `wrappers` only bans a *direct* poem/sqlx dependency, not one through `app-web`.
- **CI `scaffold` failed on the first push, outside `app-authz`.** Changing `Cargo.toml` misses CI's `.bin` cache, so sccache isn't installed yet when `make new-module` runs `cargo bin sqlx prepare`. Under `cargo bin`, `.bin/.shims` is on PATH, and `scripts/rustc-wrapper.sh` picked up its `sccache` shim through `command -v`. The shim runs `cargo bin sccache` from rustc's working directory, which for a registry crate (here hashbrown, rebuilt because saphyr turns on its `foldhash` feature) is outside the workspace, so it fails with "run-bin failed: No binaries configured in Cargo.toml". The wrapper now skips anything under `.bin/.shims/`. Read a CI job's log with `gh api repos/<owner>/<repo>/actions/jobs/<id>/logs` while its run is still in progress (`gh run view --log-failed` waits for the whole run to finish).
