# Learnings: 0055 Retiring a Schedule

- **Schedules retire automatically, subscriptions don't.** `register_schedules` (run by `migrate`) marks every row of `messaging.schedule` its build doesn't declare `retired_at`, in the same transaction as the upserts. Subscriptions still retire only through a hand-written `SELECT messaging.retire(..)` migration. Re-declaring a retired schedule reactivates it (`retired_at = NULL`, `next_at` = its next slot); a retired queue name is refused.
- **Pending vs leased runs** are told apart by `attempts`: a claim (`Worker::run_next`) raises it in its own autocommit statement. Retirement deletes runs with `attempts = 0` and dead-letters the rest (`schedule retired`), so `complete` (which ignores `dead_at`) still removes a successful in-flight run and `fail` (which needs `dead_at IS NULL`) leaves a failing one dead. A run backing off after a failure is dead-lettered too, not deleted.
- **Lock mode matters**: `register_schedules` takes `LOCK TABLE messaging.schedule IN EXCLUSIVE MODE` first. SHARE ROW EXCLUSIVE (what subscriptions use) doesn't conflict with a worker pass's `FOR UPDATE` (ROW SHARE), so it would be granted, then block the pass's `UPDATE ... next_at`, while migrate waits on the pass's row locks: a deadlock.
- **Holding a real worker pass mid-flight in a test**: insert an uncommitted deferred job with the schedule's key in another transaction; the pass's `INSERT .. ON CONFLICT` on `job_deferred_key_idx` then waits for it, having already locked the schedule's row. Poll `pg_stat_activity` for `wait_event_type = 'Lock'` before starting the competing action (see `retiring_waits_for_a_worker_pass_in_flight_..`).
- **Refreshing `.sqlx` in a worktree with no compose Postgres**: `make prepare` first builds `migrate` offline, which fails on new queries, and `scripts/migrate-unregistered.sh` uses `docker compose exec postgres`. Instead: build/run `make migrate` with the old Rust code (put new code aside), apply the unregistered modules' migrations with plain `psql` + `cargo bin sqlx migrate run`, then `SQLX_OFFLINE=false DATABASE_URL=<url>/app cargo bin sqlx prepare --workspace -- --all-targets`.
