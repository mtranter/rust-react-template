# Learnings: 0060 a streamed turn that reads as the user and pauses on writes

- **A module can't reach the server's tool surface by type**, since `Tools<C>` lives in `server`. `app_web::mcp::Toolbox` (built with `Toolbox::new::<Tools<C>>()`) is put in the API's request data by `server::build_app`, then bound to that same API with `toolbox.serve(&api)`. It holds the API through a `Weak`, so the two don't keep each other alive. A module's test driver serves one over a small `#[OpenApi]` of its own (the assistant driver's `AppOperations`).
- **Streaming operations**: poem-openapi's `payload::EventStream<BoxStream<'static, T>>`, where `T` is a `Union`/`Object`, gives `text/event-stream` in the spec, and `Toolbox`/`describe` refuse it as a tool, so it must go in `REST_ONLY`. Tests read one with `app_web::testing::Call::stream()` (each event's `data` as JSON, once the stream ends) and drop one mid-stream with `Call::hang_up()`.
- **Shutdown**: `Context::draining()` (an `app_web::Draining`) is begun by the server's `main` on the shutdown signal. Wrap any long-lived stream in `draining.bounding(..)`, or poem's graceful shutdown waits on it forever.
- **A turn writes while its owner reads.** The conversation's `get` read its row, its messages and its tool calls as three statements, and a read racing a save mixed versions (a flaky test showed a `toolCalls` message with no calls). It now reads in one `REPEATABLE READ, READ ONLY` transaction. Any aggregate whose children are read in separate statements has the same race once something writes it in the background.
- `async_trait` with a `&dyn Fn(&str)` parameter needs the higher-ranked form `&(dyn for<'a> Fn(&'a str) + Send + Sync)`. Without it the `&str` is tied to the trait's lifetime, and passing a local fails with "does not live long enough".
- rig 0.46: `DynModel<Completion>::stream(request)` yields `Item::Event(StreamEvent::Text { text, .. })` pieces; after draining it, `stream.finish().await` gives the `CompletionResponse` (`choice`, `usage.output_tokens`, `finish_reason()`). `CompletionRequest::new(last).messages(earlier)` keeps the last message as the prompt.
- Changing a migration's `CHECK` needs a new migration (0001 is applied and immutable). Postgres names an inline column check `<table>_<column>_check` (`message_kind_check`).
- The journeys' `Reference` composition now registers `assistant` with `assistant::module_with(settings, model)` and a `Directed` stand-in model (in `crates/reference/journeys/src/lib.rs`). The model is stateless because `Composition::modules()` is a plain `fn`: it does what the user's message says, if that message is `{"tool": .., "arguments": ..}` JSON.
- The seed clock's day (`seed_time(24 * 60)`) is Thursday 2 January 2025, which the system prompt states as "today".
- The only Postgres on :5432 here may be another worktree's. Tests ran against it fine, but two runs at once collide (crates/AGENTS.md gotchas).
- `make check-init` refuses any file outside `crates/reference/` that names the reference modules as a word (`notes`, `users`, ...), test code under `crates/platform/` included: the assistant driver's stand-in API speaks of "lists" for that reason. `make check-changed` doesn't catch it. To run `check-init` here, set `COMPOSE_PROJECT_NAME` to the project that owns the Postgres on :5432 (the 0059 learnings say how).
