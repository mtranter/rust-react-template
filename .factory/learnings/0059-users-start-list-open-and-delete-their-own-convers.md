# Learnings: 0059, Conversations in the `assistant` platform module

- **`make prepare` can't bootstrap a module's first queries.** `make migrate` builds the `migrate` binary, which compiles every module with `SQLX_OFFLINE=true`, so new `query!`s with no `.sqlx` entry fail it. Instead: apply the new module's migrations with `scripts/migrate-schema.sh <crate>` (and `scripts/migrate-unregistered.sh`), then `SQLX_OFFLINE=false cargo bin sqlx prepare --workspace -- --all-targets`. If `sqlx prepare` fails partway it deletes `.sqlx` entries: `git checkout .sqlx` before retrying.
- **Use a private database for that.** The dev Postgres on :5432 may belong to another worktree's compose project (`docker compose exec postgres` then says "service not running": set `COMPOSE_PROJECT_NAME` to the owning project, see `docker ps`). Create your own database (`CREATE DATABASE app_<ticket>`), point `DATABASE_URL` at it, and fill it with another worktree's built `target/debug/migrate` if yours can't build yet, so you don't put half-finished migrations in a shared `app` database.
- **The platform's seed numbers start at 1000** (`assistant::seed::MODULE`), and `scripts/new-module.sh` now counts only `crates/modules` and `crates/reference` seeds, so an app's modules keep numbering 3, 4, ... and never collide with a platform module pulled in later.
- **`make check-init`'s word scan** fails on the whole words `notes`/`users` (and the other reference names) in any line outside `crates/reference/` and `docs/platform/` that doesn't also contain `crates/reference/`: this includes Rust comments in platform crates and `crates/AGENTS.md` paragraphs, which are single long lines.
- A platform module's seed goes in the server's `seed` feature, which `scripts/init.sh` rewrites (now `seed = ["assistant/seed"]`); a new platform operation goes in `REST_ONLY` (if REST-only) and in `platform_ops` in `scripts/check-init.sh`. A new route search goes in `router.tsx` and in `init.sh`'s heredoc of it.
- poem-openapi's `Union` with `discriminator_name` + `#[oai(mapping = "..")]` generates clean TS discriminated unions with hey-api; give each variant its own Object type (the same type twice would collide in the mapping).
- sqlx `query!` takes nullable array parameters as `&v as &[Option<String>]` (and `&[Option<serde_json::Value>]` for `jsonb[]`) for `unnest(..)` inserts.
- In RTL tests, a list row's open button and its "Delete <title>" button both match a `/title/` name regex: anchor it (`/^title/`) or compare the `listitem`s' text.
