# Learnings: 0038, agent identity and audit research and Spec

- A "Spec for a human" is `status: needs-info` only. The body is written assuming each question's recommended answer, with "(question N)" on each passage that depends on it, and ends in `## Needs Human Input (factory)`. The ~150-line limit is tight with six questions: one bullet each for why, options, recommendation and dependents, and short markdown links instead of footnotes.
- `docs/platform/research/` is new with this ticket (`0001-…`), a home for the options and recommendations that back a Spec. Outside facts there carry a URL and the date checked; anything only a third party or a page summary confirmed is marked "unverified".
- Useful repo facts for audit work: every state change publishes an event in its Unit of Work (ADR 0012), all through `EventPublisher::publish` (`crates/common/persistence/src/publishing.rs`, Postgres side in `crates/common/db/src/publishing.rs`). That makes the publisher the one place an audit row can be written atomically. `Principal` has no actor, `Claims` has no `act` or `client_id` (`crates/common/web/src/auth.rs`), and `APP_JWT_AUDIENCE` is optional, which the MCP authorization spec doesn't allow for `/mcp`.
- The app can tell an agent from the SPA without token exchange, by the token's client (RFC 9068 `client_id`, or `azp`). Token exchange (`act`) adds the agent chain.
- Identity provider facts change fast: Cognito announced RFC 8693 token exchange on 2026-11-12, so check again before relying on the table in the research doc.
- Fetching outside sources through two background research agents in parallel, while reading the repo, kept this ticket short. `make check-changed` on a docs-only branch runs little.
- **CI's `init` job fails on the whole words `notes` or `users` anywhere outside `crates/reference/` and `docs/platform/`, this Learnings file included** (`scripts/check-init.sh`). Round 2 failed on "option-and-recommendation notes". `make check-changed` doesn't run `check-init`, so before committing grep your own files: `git grep -nIwE 'notes|users|note-search' -- .factory`.
