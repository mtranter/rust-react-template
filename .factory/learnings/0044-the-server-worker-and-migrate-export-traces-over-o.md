# Learnings: 0044, traces over OTLP with one span per HTTP request

- **opentelemetry-otlp's own HTTP clients bring reqwest 0.13**, whose rustls defaults to aws-lc-rs (ADR 0005 forbids it). `server::telemetry::Blocking` implements `opentelemetry_http::HttpClient` over the workspace's reqwest 0.12 `blocking` client instead. The batch span processor exports from its own thread with `futures_executor::block_on`, so a blocking client is right there; an async reqwest client would need a tokio runtime on that thread. Build the blocking client off any async runtime (it is built in a spawned thread).
- **With both `http-proto` and `http-json`, `SpanExporter::builder().build()` defaults to http/json.** The code picks the protocol itself (`protocol()`), defaulting to http/protobuf. gRPC (tonic) isn't built in.
- **tracing-opentelemetry 0.34 ignores `otel.name` recorded after a span starts** (it starts on first enter). Rename with `span.context().span().update_name(..)`.
- **poem-openapi's route for an operation renames its path parameters** (`PathPattern` is `/api/notes/:param0`). `TraceRequests::of::<Endpoints>(base)` maps each `OperationId` to the spec's path (`/api/notes/{id}`) from `OpenApi::meta()`. poem-openapi puts `OperationId` (and poem puts `PathPattern`) on the response *or the error*. `render_error` copies both onto the `ErrorBody` response it builds, or a 401/400 would lose them.
- **Trace ids in log lines come from `opentelemetry::Context::current()`**, which tracing-opentelemetry sets while a span is entered (context activation). `OtelData` is private in 0.34.
- **The SDK reports dropped spans and failed exports only through its `internal-logs` feature** (`otel_warn!`/`otel_error!` become `tracing` events on target `opentelemetry_sdk`/`opentelemetry-otlp`; with the feature off they compile to nothing). It is on in the workspace pin, and `server::telemetry::Throttled` lets each such event (keyed by its callsite name) through at most once a minute. The OTel layer filters out the `opentelemetry`, `hyper`, `h2` and `reqwest` targets, so the exporter's own HTTP calls never become spans to export.
- **`app_web::testing::Traces::install()`** sets a thread-local default subscriber with an in-memory exporter (simple processor, so spans are there as soon as they end). It works under `#[tokio::test]` and `#[app_test_db::test]` because the test's future, and the poem `TestClient` calls in it, run on the test's thread.
- `pkill -f <pattern>` run from a Bash call whose command line contains the pattern kills the calling shell too.
- **`make check-changed` in a worktree may fail at `db-up`** with "port 5432 is already allocated": the compose project is named after the worktree's directory, so it tries to start a second Postgres. Run it as `COMPOSE_PROJECT_NAME=rust-react-template make check-changed` to reuse the main checkout's container (same `docker-compose.yml`).
- **`crates/server/tests/composed_app.rs` must pass after `make init`** (CI's `init` job, `make check-init`; not in `make check-changed`), which takes the reference modules (`notes`, `users`…) off the server. A composed-app test may only call `access`' operations (the platform's, which stay); a `notes` route there is unrouted after init.
- opentelemetry-otlp 0.33: a `.with_timeout(..)` set in code overrides `OTEL_EXPORTER_OTLP_TIMEOUT`; leave it out to honour the variable (the default is the same 10 s).
