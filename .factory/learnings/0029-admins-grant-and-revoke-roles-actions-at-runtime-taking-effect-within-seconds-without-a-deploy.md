# Learnings: 0029, grants stored by the platform's `access` module and rebuilt at runtime

- **`crates/platform/` holds the platform's own modules** (today `access`). The scripts treat it like `crates/modules/` (must be registered everywhere); `make init` keeps it registered, so its four operations are the only ones in an initialised app's spec and on `/mcp` (`check-init.sh` checks both).
- **`access::module(Self::modules)`** takes the composition's own `modules` fn: what it grants from is every registered module's policies and `OPERATIONS`, its own included. Recursion is safe because the fn pointer is only called inside the provider closure.
- **Three rule sets now**: `Authorizer::baseline` (policies, no grants: what `server::authorizer` returns, enough for the worker as `System`), the stored grants once `server::rules::<C>(&ctx).refresh()` has run (the server, the composed-app test, the journeys), and `Authorizer::from_policies` (defaults in memory) for a module's own test driver, which has no `access`. A context that skips `refresh` serves only baseline rules: every non-admin gets `403`.
- **Journeys and the composed-app test apply defaults in their `TEMPLATE`** (`server::apply_default_grants`), as `migrate` does. A test DB template without it has no grants at all.
- **The poll is driven explicitly in tests** (`App::polls_the_grants`, `Access::polls`): `Rules::refresh` is one poll; `Rules::watch` is the loop `main` spawns. A second instance is `App::another_instance()` over the same pool.
- **`access.grant` works as a table name** although `GRANT` is reserved: schema-qualified names accept reserved words.
- **The SPA learns whether to show `/access` by asking for the catalog** (`useManagesAccess`); the layout asks on every screen, so `vitest.setup.ts` and `screens/main.tsx` answer `403` by default. A new frontend test with `onUnhandledRequest: "error"` needs no extra handler for it.
- **`.sqlx` for a new module**: `COMPOSE_PROJECT_NAME=rust-react-template ./scripts/migrate-schema.sh crates/platform/access/core`, then `SQLX_OFFLINE=false DATABASE_URL=postgres://app:app@localhost:5432/app cargo bin sqlx prepare --workspace -- --all-targets`. Don't point an online `cargo test` at the `postgres` database: its queries won't type-check there.
- `check-init` greps for the whole words of the reference modules' names outside `crates/reference/`: the `access` crate's tests use a module of their own (`workshop`, `gadget`), and the frontend fixtures do too.
