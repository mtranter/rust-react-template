# Learnings: 0033, `access` records who signs in, and the Users tab

- **Shared Postgres across worktrees.** Port 5432 often belongs to another checkout's compose project, so `make db-up`/`db-wait` fail, or, worse, `make migrate` would apply this branch's migrations to someone else's dev database. Run a private one (`docker run -d --name pg-NNNN -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -e POSTGRES_DB=app -p 5441:5432 postgres:17-alpine`) and pass `DATABASE_URL`/`TEST_DATABASE_URL` to make, skipping the compose targets: `make -o db-wait -o db-up check-changed DATABASE_URL=postgres://app:app@localhost:5441/app TEST_DATABASE_URL=postgres://app:app@localhost:5441/postgres`.
- **New `query!` + new migration: chicken and egg.** `migrate` can't build until `.sqlx` knows the new queries, and `sqlx prepare` needs the migrated tables. Apply each schema's migrations by hand with `cargo bin sqlx migrate run --source <crate>/migrations --database-url "$URL?options=-csearch_path%3D<schema>"` (common/db's are schema `messaging`), then `SQLX_OFFLINE=false DATABASE_URL=$URL cargo bin sqlx prepare --workspace -- --all-targets`. `scripts/migrate-schema.sh` does the same, but only against the compose container.
- **Request data from a module beyond its service**: `Module::providing(fn(&Context) -> T)` (added here) layers more data onto the module's provider. `access` uses it to put its `Arc<dyn PrincipalResolver>` (`access::sign_ins`) in front of every request; a module test driver adds the same data to its `TestApi` wiring by hand.
- **`Claims` now carries `name` and `email`** (OIDC's standard profile claims). Tests sign tokens with a profile through `JwtVerifier::sign(&Claims::lasting(sub, ttl)?.named(..).with_email(..))`.
- **"Writes nothing" is shown with Postgres' `xmin`**: the driver reads `xmin::text` of the row, and every write changes it. Keep the domain's staleness test (`>= SEEN_WITHIN`) and the SQL's (`last_seen <= now - 1h`) on the same boundary: an off-by-one between them showed up only at exactly the hour.
- **Subjects aren't an aggregate**: an upserted, unversioned record of sightings that publishes nothing. That's a deliberate exception to the `db/` "never an upsert" rule, recorded in ADR 0041's amendment and the glossary's **Subject**.
- **Adding an `access` operation** touches four lists besides the code: `composed_app.rs`' `TOOLS`, the `TOOLS` that `scripts/init.sh` writes, `scripts/check-init.sh`'s `access_ops`, and `OPERATIONS`.
- **Frontend tests**: a toast lasts about 5 seconds, so a slow test (many `selectOptions`) should assert it right after the click, not at the end. `getByRole` ignores content an open or closing alert dialog has made `aria-hidden`; after an error toast, query the table with `getByText`.
- **`scripts/init.sh` rewrites `frontend/src/router.tsx` wholesale.** A change to `/access`' search (a new tab, a new search param) must be made in init's copy too, or the inited app fails `tsc` (CI's `init` job). Without a free 5432 for `make check-init`, check the frontend half instead: clone the branch, run init's section 5 with `title`/`name` set, `pnpm run generate`, then `typecheck`, `vitest`, `biome ci` and `lint:imports`.
- **`check-init` forbids the lowercase word `users` (and `notes`) anywhere in the inited app** outside `crates/reference/`, `docs/platform/` and build records: it is the reference module's name (`scripts/check-init.sh`, `git grep -w`, case-sensitive). The platform's own screens and docs must say "subjects", "user" or "Users" instead; so the Users tab lives at `?tab=subjects`. Grep a change for it with `git grep -nIwE 'users|notes' -- frontend/src/features/access frontend/src/pages/access-page.tsx frontend/src/router.tsx frontend/src/test/access* frontend/AGENTS.md`.
- **Running the full `make check-init` without 5432:** copy the tree as `check-init.sh` does, point `Makefile`, `scripts/check-init.sh` and `scripts/migrate-schema.sh` at a private Postgres container (`localhost:5441`, `docker exec -i <container> psql` in place of `docker compose exec -T postgres psql`, `db-up` a no-op, `db-wait` polling the container), commit the copy, and run its `scripts/check-init.sh`.
