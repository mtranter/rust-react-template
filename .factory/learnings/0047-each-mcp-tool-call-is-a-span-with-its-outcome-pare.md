# Learnings: 0047 MCP tool call spans

- The app's `TraceRequests` sits outside the whole router, so it sees only `POST /mcp`; the in-process call a tool makes bypasses it. `mcp::endpoint` therefore wraps the API it calls in its own `TraceRequests::of::<S::Api>(S::BASE)`, which makes the REST span a child of the current (tool) span: the in-process request carries no `traceparent`.
- The tool span is opened in `OpenApiTools::call` with `otel.name` set before it starts (rename only works then), and `is_error` / `otel.status_code` declared `Empty` and recorded after the call. The operation is resolved first, so a name no tool has spans as `tools/call` instead of minting a span name per bogus tool.
- `McpSession::call` asserts a JSON-RPC error is `-32602` (invalid params), so an unknown tool (`-32601`) can't be driven through it; the refused-before-request path is tested with an extra argument instead.
- `app_web::testing::Traces` is per-thread; `#[tokio::test]`'s current-thread runtime keeps the MCP session's work on the test thread, so the spans are captured.
- Merge gate: on this machine 5432 is held by the main checkout's Postgres (`rust-react-template-postgres-1`), so `make check-changed` fails at `db-up` in a worktree. Fix without touching tracked files: a gitignored `.env` (the Makefile includes it, docker compose reads it) setting `COMPOSE_FILE=docker-compose.yml:target/factory-compose.override.yml`, whose `ports: !override ["5447:5432"]` moves the worktree's Postgres, plus `DATABASE_URL`/`TEST_DATABASE_URL` on 5447.
- Rebase onto main (after 0049/0050/0051/0053/0056): the only conflict was `crates/AGENTS.md`'s Traces paragraph, which main renamed "Traces and metrics" and extended with query spans; the MCP tool-span sentences slot in after the `TraceRequests` sentence unchanged.
